# ============================================================================================
# SHIP MESH ORIENTATION
#
# One line per mesh: <name> <pitch> <yaw> <roll> [scale] [spin|nospin]
# Edited and reloaded while the game runs (F10) — no recompile.
#
# The game's convention is Unity's: +Z is forward (the bow), +Y is up (the dorsal surface).
#
#   flying sideways?      try  0 90 0   or  0 -90 0
#   flying belly-first?   try  -90 0 0
#   flying backwards?     add  180 to the yaw
#
# ---- glTFast MIRRORS X ON IMPORT, AND EVERY YAW BELOW ACCOUNTS FOR IT (2026-10-11) -------------
#
# glTF is right-handed, Unity is left-handed, and com.unity.cloud.gltfast 6.10.1 converts by negating
# X — Runtime/Scripts/Jobs.cs, ConvertVector3FloatToFloatInterleavedJob: `tmp.x *= -1;` for every
# position and normal, and NodeExtension.GetTransform: `-node.translation[0]`. So a hull whose nose is
# on glTF -X arrives in Unity with its nose on +X, and the yaw that carries it to +Z is -90, not +90.
#
# This file used to say +90 for exactly those hulls. The per-hull READINGS were right (they were taken
# off the raw-glTF silhouette sheet); the conversion from reading to yaw ignored the mirror, so the
# whole generated fleet was flying TAIL-FIRST. Every +-90 line was negated, and then all 145 hulls
# were checked one at a time on `tools/ship-orientation-sheet.mjs`, which draws each hull the way
# the game will — glTF x negated, then this file's rotation — with the bow at the top of every cell.
# `tools/bake-ship-hardpoints.mjs` prints the same verdict as numbers.
#
# THE AXES IN THE COMMENTS ARE RAW glTF AXES (what ship-silhouettes.mjs and measure-bow.mjs report):
#
#   nose on raw -X   ->   0 -90 0        nose on raw +Z   ->   0   0 0
#   nose on raw +X   ->   0  90 0        nose on raw -Z   ->   0 180 0
#
# THREE HULLS ARE LONG ACROSS THEIR OWN BEAM: a manta ray carrier, a sea-turtle colony ship and a
# Terran scout aeroplane are all WIDER than they are long, so "the longest axis" finds the wingspan.
# Their lines say so.
#
# STATIONS DO NOT HAVE A BOW. Every one sits with its axis of symmetry on Y (discs flat, the Terran,
# Cryithn and Sylvan relay masts standing on end, the Pyrothian Hyper-Relay an upright gate), so they
# take the identity rotation — Y is not touched by the mirror — and are marked `spin` or `nospin`.
#
# Re-running tools/make-orientation-manifest.mjs OVERWRITES THIS FILE and will undo all of it. Never
# run it. After changing a line, re-run the orientation sheet AND tools/bake-ship-hardpoints.mjs —
# the plumes and gun points are baked against these rotations, and a stale bake falls back to bounds.
# ============================================================================================
